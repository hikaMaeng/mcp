# 출력 계약의 보증 범위

정상적으로 파싱된 MCP `tools/call` 요청에서 도구 이름이 `websearch`이고 서버가 응답을 반환할 수 있는 경우, 성공과 도구 실행 오류 모두 [공개 출력 스키마](../schemas/websearch.output.schema.json)에 맞는 동일한 JSON 형태를 반환한다.

1. 검색 요청은 프롬프트의 JSON 데이터 구역에만 넣는다. 셸 명령이나 CLI 옵션으로 조합하지 않는다.
2. 프롬프트는 검색 필수, 검색 자료에 근거한 결과, 허위 URL·날짜 금지, JSON만 출력을 지시한다.
3. `codex exec --output-schema`로 모델의 최종 응답에 JSON Schema를 적용한다.
4. 서버는 완료된 검색 이벤트와 완료된 turn을 확인한다. 모델이 본문에서 검색했다고 주장하는 것만으로 통과시키지 않는다.
5. 모델의 최종 JSON을 엄격히 검증한다. 누락·추가 필드, 타입 오류, 잘못된 URL·날짜는 실패 처리한다. Markdown 제거, 임의 값 채우기, 실패를 빈 검색 성공으로 바꾸는 처리는 하지 않는다.
6. 서버가 출처 중복 제거, 결과 수 제한, 연속 순위, 고정 모델 정보, 응답 시각과 오류 정보를 구성한다. 모델이 메타데이터를 결정하지 않는다.
7. 최종 직렬화 결과를 다시 검증한다. 성공·오류의 필드, 결과 수·순위·중복 및 상태 일관성을 검사한다.
8. `structuredContent`와 텍스트 JSON에는 같은 객체를 사용한다. 테스트는 독립 JSON Schema 검증기로도 확인한다.

프롬프트만으로 보증하지 않는다. 프롬프트를 모델이 따르지 않아도 검증에 실패하면 정해진 오류 응답으로 종료한다. 자동 재시도는 하지 않는다.

## 경계

- 검색 내용의 사실성, URL의 실제 접근 가능성, 검색엔진 원래 순위, 동일 질의의 동일 결과는 보증 대상이 아니다. 제목·요약·게시일은 모델이 검색 자료에서 정리한다. CLI 검색 이벤트는 개별 결과 URL의 출처 증명까지 제공하지 않는다.
- 손상된 JSON-RPC, 알 수 없는 도구 이름, 초기화 실패는 MCP 프로토콜 오류다. 연결 단절·프로세스 강제 종료·MCP 취소는 응답 자체가 없을 수 있다. 서버의 JSON 형태 보증과 전달 보증은 구분한다.
- Codex 로그인, 네트워크, 계정 사용량과 `gpt-6-luna` 접근 권한이 필요하다. 다른 모델로 대체하지 않는다.
- CLI `0.155.0`에서 실제 실행했다. `--ignore-user-config`를 지원하지 않는 이전 CLI는 실패할 수 있다.
- 사용자 CLI 설정을 읽지 않으므로 커스텀 provider·프록시 등 config.toml 설정도 상속하지 않는다. CLI 인증은 기존 `CODEX_HOME`을 이용한다.
- read-only 샌드박스, shell/app/subagent 비활성화, 별도 임시 작업 폴더를 사용한다. 이것을 운영체제 전체에 대한 별도 보안 경계로 간주하지 않는다.
